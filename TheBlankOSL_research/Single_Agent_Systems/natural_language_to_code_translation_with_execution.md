# Natural Language to Code Translation with Execution

## Abstract

**Problem:** Generative models can generate code from natural language descriptions but struggle to consistently select the correct program from multiple candidates.

**Solution:** The paper proposes MBR-EXEC, a method that selects programs based on execution results, improving the model’s performance in natural language-to-code tasks.

**Results:** Execution or simulated execution improves the selection of correct programs compared to methods that don't use execution information.

## Introduction

**Challenge:** Selecting a single correct code implementation from multiple generated candidates is difficult, especially when the generated code might have different syntax but similar functionality.

**Objective:** Introduce a program selection method that uses execution results to identify the best code among generated candidates.

**Key Insight:** Pretrained models spread the probability across multiple correct code implementations that perform the same function. By executing code and comparing results, better selections can be made.

## Proposed Approach (MBR-EXEC)

MBR-EXEC (Minimum Bayes Risk Execution-based Decoding) is a decoding method designed to improve the selection of correct programs generated by models in natural language-to-code translation tasks. It works by leveraging execution results to compare multiple candidate programs and select the best one based on their behavior rather than just their syntax or structure.

Here’s a step-by-step breakdown of what MBR-EXEC does:

1. **Sampling Candidate Programs:**

   - A large pretrained model (like Codex) is prompted with a natural language description of a task (e.g., "Write a function that adds two numbers").
   - The model generates multiple candidate programs that could potentially solve the task.

2. **Execution-Based Scoring:**

   - Each generated program is executed on a set of test inputs (e.g., input values like `add(1, 2)`).
   - The execution results (outputs) of these programs are collected.

3. **Calculating Minimum Bayes Risk:**

   - The goal is to select the program whose execution results are the most consistent with the other candidates.
   - Bayes risk is calculated by comparing the execution results of each program with the others. The candidate program that has the smallest discrepancy (minimal execution difference) from other candidates is chosen.
   - In simpler terms, if multiple programs produce the same or similar outputs on given inputs, they are likely implementing the correct logic. The program that agrees the most with the others in terms of execution is selected as the best one.

4. **No Need for Ground-Truth Outputs:**

   - Unlike traditional evaluation methods that rely on comparing generated code to a correct reference code (using BLEU scores, for example), MBR-EXEC does not require a correct solution to be known in advance.
   - It simply compares how the generated programs behave (i.e., their output) on test inputs and uses this behavior to make its selection.

### Why is MBR-EXEC Useful?

- **Program Semantics Over Syntax:** It focuses on the functionality (semantics) of the generated programs rather than their syntactical similarity to a reference solution.
- **Few-Shot Setting:** It improves performance in few-shot scenarios, where the model is given only a few examples to learn from.
- **Generalization:** It works across different programming languages (Python, SQL, Bash) and tasks, as long as the programs can be executed.

### Example

Imagine you ask a model to generate code for adding two numbers. The model generates three candidate solutions:

1. `def add(a, b): return a + b`
2. `def add(x, y): return x + y`
3. `def add(a, b): return a - b`

The first two programs give the correct result (`add(1, 2)` returns `3`), but the third one gives an incorrect result (`add(1, 2)` returns `-1`). MBR-EXEC compares the execution results and selects one of the first two programs, as their execution behavior is consistent with each other and likely correct.

## Experiments

### Datasets

Evaluated on three datasets:

- **MBPP (Python):** Python programming tasks.
- **Spider (SQL):** Text-to-SQL tasks.
- **NL2Bash (Bash):** Translating natural language to Bash commands.

### Metrics

Performance is measured using execution accuracy (whether the code executes correctly on test inputs).

## Results

- MBR-EXEC outperforms baselines that do not use execution results across all datasets.
- The approach is particularly strong in Python and SQL tasks, where execution-based selection shows significant improvement.

## Analysis

### Effect of Sample Temperature

- Lower temperatures (below 0.5) in the sampling process yield better performance in generating candidates.

### Effectiveness of Few-Shot Prompts

- Different 3-shot prompts provide better results than concatenating all examples into one large prompt.

### Executability vs. Execution Results

- Simply checking whether a program can execute is not enough.
- MBR-EXEC’s focus on actual execution results leads to better program selection.

## Conclusion

- MBR-EXEC is a strong and effective selection mechanism for natural language-to-code translation.
- Future research could incorporate execution results during the model’s training phase to further improve performance.

## Key Takeaways from the Research

- **Execution Results Matter:** Using execution results significantly improves the selection of correct programs, even without access to the ground truth.
- **Broader Impact:** The method can be applied across multiple programming languages and datasets, making it versatile for natural language-to-code tasks.
- **Potential Applications:** This approach could improve real-world applications like automatic code generation from natural language, enhancing productivity in coding tasks.

---

This research highlights the importance of not just generating code that looks correct but also ensuring it behaves correctly when executed. The MBR-EXEC framework provides a reliable way to choose between multiple generated programs, making it an essential advancement for natural language-to-code translation systems.
